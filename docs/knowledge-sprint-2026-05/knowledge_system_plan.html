Six gaps versus the goal

  • No review workflow. Author publishes directly.
  • No link to Job. Internal lessons cannot reference their source task.
  • No external-reference shape. No source, URL, verified date, reliability.
  • No AI structuring step. No seam, no dry-run, no gates.
  • No revision history. Edits overwrite. No diff.
  • No freshness sweep. Stale articles erode trust silently.

Product vision

Useful company memory. Reviewed lessons. Reviewed external references.

02 / 15

A worker who solved a problem yesterday should be able to make tomorrow's worker 10 minutes faster. A worker who found a great external doc should be able to keep the team from re-finding it.

Yes

  • Reviewed internal lessons sourced from completed jobs.
  • Reviewed external references (links, RFCs, vendor docs).
  • Type-aware editor (6 kinds).
  • Reliability tier for every article.
  • Freshness pill + sweep.
  • Optional LLM structuring as advisory aid.
  • Audit trail on every state change.

No

  • Not a customer-facing wiki.
  • Not a marketing CMS.
  • Not a personal notebook.
  • Not the SOP system-of-record for the accountant.
  • Not a chat archive.
  • Not a CRM for "notes about people".
  • Not a doc generator that writes by itself.

Task-to-knowledge flow

From a reviewed job to a published article.

04 / 15
Job moves to status=reviewed -> [optional] checkbox in MarkDoneSheet: prefill draft now -> button on /my-jobs/[id]: "Create knowledge article from this job" -> opens /knowledge/new with kind=internal_task_lesson -> sourceJobId, sourceWorkReportId pre-set -> author writes Problem / Cause / Fix / Verification -> [optional] click "Structure with assistant" (dry-run V1) -> Submit for review -> Reviewer queue: admin reads, comments, approves -> Publish -> Appears in /knowledge list + global search scope -> Cross-link visible from the source job's detail page
Author cannot be reviewer. Server-side guard. Same job's assignee remains the author by default; admin reviews.

External reference flow

Paste a URL. Add notes. Review. Publish.

05 / 15
Employee finds a useful link -> Click "+ Add external reference" on /knowledge -> /knowledge/new/external form: URL, externalSource (vendor name), summary, whyItMatters, tags, reliability tier (defaults to single_source) -> Canonical URL hashed (SHA-256). Duplicate -> show existing. -> Submit for review -> Reviewer queue: senior employee or admin reviews -> Approves or requests changes (cap 2 cycles) -> Publish -> Last verified stamp = approval time -> Freshness sweep (180-day default per type) notifies reviewer when the article goes stale; never auto-acts.
V1 ships without auto-fetching the page title (SSRF risk needs more design). Author types the title. V2 enables auto-fetch behind a flag.

Review and approval workflow

Six statuses. Nine transitions.

06 / 15
draft ----submit----> pending_review draft --AI structure-> ai_structured ----submit----> pending_review pending_review ---approve---> approved ---publish---> published pending_review ---request-changes---> draft (cycle counter ++) approved ---un-approve---> pending_review (admin only) published ---archive---> archived (admin only; comment) archived ---un-archive---> draft (admin only) published ---rescind---> archived (410 Gone) (admin; legal/safety)

Reviewer rules

  • Author cannot be reviewer of own revision.
  • Cycle cap = 2 (changes requested). Admin arbitrates after.
  • SLA: pending_review for > 5 working days triggers a soft prod via notification.
  • Approve and publish are distinct buttons. Mirrors receipts pattern.

Permissions and security

12 threats. 27 actions x 4 roles. LLM behind three gates.

10 / 15
#ThreatMitigation
1Prompt injection in worker writeupRedaction pre-pass + reviewer always sees original
2Secret leak in published articleEditor-time scanner (9 regex patterns) + reviewer warn + weekly re-scan
3SSRF via auto-fetch external URLV1 manual title; V2 server-side fetch with allowlist
4XSS via raw HTML in MarkdownServer-side sanitizer (allowlist tags + attrs)
5Draft data crosses department boundaryDefault department_only for internal_task_lesson
6Author approves own revisionServer-side same-actor guard
7Vendor data leakage via LLM callThree gates + redaction + dry-run default

Three-gate LLM posture (mirrors receipts)

  • knowledge_ai_structuring_enabled flag (default false)
  • ALLOW_KNOWLEDGE_AI env (default unset)
  • knowledge_ai_provider_verified flag (default false)
Any false = dry-run mode (deterministic local transform). Real LLM call blocked until all three pass.
