Israel compliance pillars (cited)

Authoritative findings from israel_compliance_audit.md. Citations inline; full URL list at the end of that document.

03 / 12

VAT and rates

  • Standard VAT rate 18% in 2026. (IL VAT Law; budget 12/2025)
  • Zero-rated and exempt categories apply per the VAT Law; IT services to Israeli clients = standard rate. (VAT Law)
  • Store as basis points (1800 = 18.00%) - matches current schema.

Allocation numbers (מספרי הקצאה)

  • NIS 10,000 (incl. VAT) threshold from 2026-01-01. (VAT Implementation Order 01/2025)
  • NIS 5,000 from 2026-06-01. (same)
  • Applies to tax invoices and combined tax-invoice-receipts.
  • SHAAM API: OAuth2 user-restricted, JSON, sandbox URL published. Auth expires every 3 months.

Documents and numbering

  • Six document types map cleanly to the existing ReceiptDocumentType enum.
  • Sequential numbering per type and year. Reservation must be atomic (already implemented via ReceiptDocumentSequence).
  • Cancellation of a finalized tax invoice is not legal. Only credit notes correct it. Must be blocked at DB and route.
  • Annual reset vs continuous numbering: unverified, accountant must confirm.

Reporting and retention

  • PCN874 threshold drops to NIS 500K turnover from 2026 (was 2.5M). Build PCN874-ready data, defer the filer.
  • Retention: per Bookkeeping Order; accountant must confirm exact years.
  • PDF/A vs any non-mutable PDF: unverified, accountant must confirm.
  • Language: Hebrew document primary; optional English alongside.
The compliance audit explicitly flags items as "unverified, needs accountant review". The accountant gate in Section 7 of the plan consolidates these. The implementation will NOT invent values.

Document, PDF, and template work

A working tax invoice and credit note in Hebrew - the V1 visible artifact.

07 / 12

Choices

  • Renderer: Puppeteer (headless Chromium). HTML/CSS source; supports Hebrew RTL.
  • Hebrew font: Heebo (Open Font License), embedded.
  • Template: React component rendered server-side, behind lib/pdf/render.ts seam for future swap.
  • Header snapshot: stored as JSON on the finalized receipt so future CompanySettings edits do not rewrite history.
  • Caching: render once on finalize, store PDF as an Attachment, serve cached on download.

Template required content

  • Legal name + VAT number + address (from CompanySettings snapshot).
  • Document type label in Hebrew (חשבונית מס וכו') and English.
  • Sequential document number + year.
  • Issue date (and payment date for receipts).
  • Client name + tax ID + address.
  • Lines: description, quantity, unit price, VAT rate, line total.
  • Subtotal, VAT, total. Currency code. Exchange rate when non-ILS.
  • Allocation number when present (above threshold).
  • Footer block from CompanySettings (Hebrew + English).
  • Page numbers, accountant disclaimer when in draft.
Accountant must review a rendered sample of: a draft, a finalized tax invoice, a credit note, before the flag is flipped on in production.

Country toggle architecture

Israel-only live. Future countries pluggable, blocked at runtime.

08 / 12

Schema

  • New CountryCode enum: IL, _OTHER.
  • CompanySettings.country typed as enum (was free-form String).
  • Migration: cast existing value "IL" to enum; default IL.

Code

  • lib/compliance/country.ts: getCountryProfile(code) returns interface.
  • Interface fields: defaultVatBasisPoints, requiresAllocation(amount, type), documentLanguageDefault, numberingResetAnnually, retentionYears, document type catalog.
  • Receipts and Financial Documents read defaults through this profile.
  • Only IL implemented; _OTHER throws with a clear message.
  • Country chip in admin header pulls the active country.
The country toggle is an architectural seam, not a sales feature. It exists so future country work lands without scattering Israeli assumptions across the codebase.

Tests and QA gates

Per-wave ship gate plus a final accountant gate.

09 / 12

Per-wave ship gate

  1. pnpm typecheck && pnpm lint && pnpm test all green.
  2. Each new route has a contract test (happy + permission denial).
  3. Each new table migration applies on a fresh DB; seed runs clean.
  4. Every new UI string in both en.json and he.json (parity test enforces).
  5. A reviewer has read the PR and signed off in writing.

Accountant gate (Wave 5)

  1. Render a draft invoice, a finalized tax invoice, a credit note. Accountant reads each PDF.
  2. Sandbox SHAAM call returns a fake allocation number end to end.
  3. Field list on a tax invoice matches the Bookkeeping Order list.
  4. Numbering policy (annual reset vs continuous) is set per accountant guidance.
  5. Retention period stored on CompanySettings; sweeper deferred or staffed.

Test types planned

Risks and tradeoffs

Each risk has a mitigation. Top three are pilot-blocking.

11 / 12
#RiskLIMitigation
R1Allocation thresholds change mid-yearHighMedThresholds live in the IL country profile; one-file edit.
R2Puppeteer cold-start costMedMedCache PDF on finalize as an Attachment; reuse.
R3Hebrew font missing glyphsLowMedEmbed Heebo; fallback to system Hebrew; test rare characters.
R4SHAAM 3-month auth lapses unnoticedMedHighNightly cron checks; failure raises a notification to admins.
R5Accountant takes longer than 2 daysHighLowWave 5 is operational; code waves do not block.
R6DB trigger differences dev vs prod PostgresLowMedCI runs Postgres 16; trigger applied via raw-SQL migration.
R7Backfilling linkedReceiptId on old paymentsLowLowNew writes only; no backfill in V1.
R8Credit-note duplicate guard blocks legit re-issueLowMedOverride path documented; not built in V1.
R9Country toggle adds friction for IL-only changesLowLowIL profile is a TS module; single-file edits.
R10Puppeteer not allowed on hostMedMedRun renderer in a dedicated worker; lib/pdf/render.ts seam swaps to React-PDF.

Top three tradeoffs

  • Compliance correctness vs velocity. Wave 0 cannot be shortcut. Accountant gate is real.
  • Scope vs polish. V1 ships allocation skeleton not real SHAAM call. The skeleton is wired correctly so the upgrade is small.
  • Speed vs flexibility. Puppeteer is fast to ship; React-PDF is faster at runtime. Start with Puppeteer behind a seam.
