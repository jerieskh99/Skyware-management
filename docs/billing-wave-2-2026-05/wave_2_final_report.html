01 - Executive summary

What shipped, in one breath.

Admins set a lateness rule on a payment. When it lapses, the system notifies admins first (dashboard + email), shows the full context, and waits for a decision: approve, delay, cancel, or send now. The client reminder email renders from an editable bilingual template. Hourly-bank clients get a 90% usage alert. Admins can also contact any client manually from Billing with a previewed, logged email. Everything is audited. Nothing is transmitted for real in V2.

02 - Revised Wave 2 scope

Four features. Tight guardrails.

In scope

  • Per-payment lateness rule (days or weeks)
  • Admin-first notify + review queue (approve/delay/cancel/send-now)
  • Client reminder email from editable bilingual template
  • Hourly-bank 90% alert (dashboard + admin + client), 30-day dedup
  • Manual contact from billing/payment/bank with preview + history
  • Email template editor + email log
  • Audit on every event; admin-only; flags default off

Out of scope (deferred)

  • Real email provider integration (V2 is transport-stubbed)
  • Delivery / bounce webhooks
  • Open / click tracking
  • In-app client reply inbox
  • Per-client language preference
  • Bulk remind-all
  • SMS / WhatsApp
03 - Reminder flow

Admin sees it first. Client only after a decision.

1

Rule set

Admin sets lateness (days/weeks) on a payment.

2

Trigger lapses

Cron finds the overdue payment, creates a reminder.

3

Admin notified

Dashboard notification + admin email. Full context shown.

4

Admin decides

Approve / delay / cancel / send now.

5

Client email

Rendered from template. Test mode - captured, not sent.

Optional policy: a per-payment "auto-send after N minutes of admin notification" window. Off unless an admin sets it. Even then, the email is test-mode in V2.

05 - What was debugged

Two real issues, both resolved.

  • Wrong-worktree schema build. The DB wave landed in a non-canonical worktree. The byte-identical delta (5 enums + 4 models, nothing else) was copied to canonical team1, verified, committed. No data loss.
  • lucide-react test failures (pre-existing, 3 files). Root cause: lucide-react@0.469.0 has no exports field and a corrupt ESM build (a missing icon file). Fixed via a deterministic stub alias in vitest.config.ts. The suite is now fully green for the first time in several waves.
QA ran 61 tests against the Wave 2 routes and lib. Zero functional defects found in the Wave 2 code itself.

09 - Remaining risks

Known and contained.

  • Real email not yet wired. When it is, add a transmit-path test with a mocked provider + security review. V2 cannot send, so no current risk.
  • Billing-list manual-contact no-email guard is backend-only (list query selects only id + name). Acceptable; the 422 surfaces clearly.
  • EmailLog body retention policy needed before real sending is enabled (PII).
  • Client emails default Hebrew until a per-client language column lands.
